# Collection and generator hills 131–210

Baseline: `2068408` (0.16.0). This ledger covers the 26 assigned collection and
QuickCheck experiments. Timings below are microseconds, recorded serially under
`flock /tmp/typeclasses-round3-bench.lock`, from immutable source snapshots.
`bench/artifacts/round3-collections.json` contains source, workload and
experiment SHA-256 hashes, toolchain versions, all seven observations per side,
and listener counts. The Gen follow-up in
`round3-collections-gen-properties.json` contains the final
direct-array-length-draw fix and supersedes the initial Gen qualification; its
source hashes identify that later boundary. Release comparisons include shared
core changes; explicitly marked counterfactuals use the same current
dictionary/core. These are shared-host observations, without confidence
intervals. Construction, JIT warmup and GC can change rankings; no universal
throughput claim follows.

Reproduce in an immutable checkout. Copy the complete src tree, deno config,
benchmark driver and its three imported experiment files together. Copy
`src/quickcheck.ts` to `src/quickcheck_original.ts` there and reverse-apply
`bench/experiments/round3_gen_registers.patch` to that copied file. Then run:

```sh
flock /tmp/typeclasses-round3-bench.lock deno run --no-check --allow-read --allow-write \
  bench/round3_collections.ts /tmp/typeclasses-round3-baseline-2068408 \
  file:///absolute/snapshot/src/quickcheck_original.ts
```

An optional third argument selects a workload-name substring and writes a
separate suffixed artifact. The initial, frozen combined candidate capture is
retained as `round3-collections-candidates.json`; it records failed designs and
mixed release comparisons, not final claims. The earlier tuple object-control
capture used a different flattener initially; only the matched complete tree
prototypes in the final artifact support hill 164's decision.

The Gen follow-up driver is `bench/round3_gen_qualification.ts`. It alternates
original/register order for eleven blocks, constructs fresh plans outside the
first-draw timer, separately times construction plus execution, and runs 10k
properties that inspect actual scalar, array, Maybe and composed-generator
values. Fresh plans share one process; these are not cold-process import times.
`round3-collections-gen-qualification.json` preserves the original failing array
control, `round3-collections-gen-qualification-fixed.json` records the
direct-draw fix with trivial properties, and
`round3-collections-gen-properties.json` records the final value-checking
properties. Each includes both source hashes and raw observations. No graph is
preexecuted in the fresh-plan cases.
